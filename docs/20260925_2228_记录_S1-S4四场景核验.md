### S6：S4/S5（立项自动指定）与手工 /auto-nn-plain、/auto-nn-reference 是什么关系？指定了还需要手工技能吗？

**关系 = 「定什么」与「怎么执行」两层，不是二选一**：
- S4/S5 立项指定 = 把起步尺子意图落成机读 intent，首轮 auto-run 自动带任务（plain 直接跑 1 轮；reference 还要过校准硬门）。
- 手工技能 = 运行期尺子管理通用入口：立尺/换尺（`--replace`）/补尺，含 status 先报、人确认、「每场景每把尺最多一行」硬边界（PROTOCOL.md §6）。

**指定了之后手工技能还要不要？要，但「首轮触发」职责被替代**：
- 首轮：plain 已由 intent 指定 → auto-run 按提示直接跑，不再需要手工 `/auto-nn-plain` 触发（`nn_baseline.py status` 也会报已有 plain，每场景一行防重复）。
- 仍需要手工技能的场景：① 答卷没定尺（无 O3 lock）时首轮自推仍要按技能纪律走；② 运行期换尺 `--replace`；③ 多场景项目里未指定场景的补尺；④ WPL 被动兜底（round≥2 无锚仍发 plain-anchor-init 段，代码在）；⑤ reference 校准不过线时的人工介入入口。
- **结论：不能删**；若删，①-⑤ 五类场景无入口。

**用户澄清（09-26 问：「没手动触发时它们做了没有？做过了再手动触发会重做吗？」）——代码事实四答**：
1. **答卷指定 plain** → intent 落盘，round=1 首轮提示自动带 plain 任务，agent 跑完 TSV 行 baseline_tag=plain——**自动做了，不需手动触发**。
2. **答卷指定 reference** →（S5 修后）round=1 自动发立尺提示走 `/auto-nn-reference` 流程，但**校准硬门不自动放行**：check-source-cal 不过线就只落 ledger_midpoint 占位，等人工。
3. **模板项目/迁移仓自带**（已有锚值或 TSV 已有 reference 行）→ 发射器检测到信号直接不发，读侧公告栏直接用现成尺。
4. **已经做过、再手动触发** → `stamp_tag`（lib/baseline_stamp.py:335）每场景每 tag 唯一，**直接拒绝不重做**（报错「场景已有 plain/reference，不要再贴；要换这次的候选请 --replace」）；`--replace` 才把旧行置 none 再贴新行，且有保护（不能把当前最好贴成 reference 自比、plain 行不能改贴 reference）。
5. **答卷和模板项目都没指定** → 已按用户拍板另立 **S7**（见下）。

### S7：答卷和模板项目都没有 plain / reference 时怎么办？（09-26 拍板 = 按原有逻辑，无需改动）

## 5. S1–S7 逻辑关系总览（09-26 整理）

**一组「建仓三入口」+ 一片「起步尺判定树叶」+ 一条「横切边界」**：

```
建仓入口（S1/S2/S3，只决定仓怎么来）
  S1 --workflow build    从数据新建（无家底）
  S2 --workflow migrate  整体迁移参考仓（保真）
  S3 --workflow migrate+答卷  迁移并按答卷改造
        │  三条入口汇入同一条 init 尾部：
        ▼
  resolved lock → render_init_blocks → write_intent → 首轮 render
        │  分叉点 = write_intent 读 O3 lock（起步尺声明）
        ▼
  ├─ 有 O3.PLAIN=            → S4：start_runs=plain，首轮发 plain FIRST-ROUND（带 plain_recipe）
  ├─ 有 O3.REFERENCE=        → S5：start_runs=reference 或 plain+reference，
  │                              首轮发 reference FIRST-ROUND（带 check-source-cal/ledger_midpoint 硬门原文）
  └─ 两者都没有               → S7：按原有逻辑（缺省照推 plain + skipped 标记留痕；
                                 reference 只走满 10 轮被动兜底；手工技能随时可用）
```

**S6 是横切边界**，不在判定树上：自动指定只管**首轮「定什么」**（plain 自动跑；reference 自动发立尺提示、硬门不自动放行）；运行期的立尺/换尺/补尺/校准归手工技能 auto-nn-plain / auto-nn-reference。已做过再手动触发 → stamp_tag 直接拒绝（重复贴要 --replace；当前最好不能贴成 reference 自比；plain 行不能改贴 reference；reference 贴前必须过来源校准硬门）。

**原有逻辑零改动对照**（S5/S7 实施后，以下全部保持原样）：

| 原有逻辑 | 现状 |
| --- | --- |
| `_intent_wants_plain(None)=True`（无 intent 缺省推 plain） | 未动，S7 依赖它 |
| 满 10 轮被动兜底 `_emit_reference_start`（REFERENCE_AUTO_AFTER_ROUNDS=10） | 未动，S7 依赖它 |
| 手工技能 auto-nn-plain / auto-nn-reference | 未动，S6 结论=保留 |
| stamp_tag 保护（--replace / 自比 / plain→reference / 校准硬门） | 未动，S6 运行期实证 |

**S5 修前的坑（为什么会有 S5）**：修前 write_intent 不认 O3.REFERENCE，reference-only 答卷会掉进「无声明」分支且缺省**误推 plain**；d2b8832 补上 reference 分支与首轮发射器后，三片叶子才完整覆盖判定树。S1–S3 入口与 S4–S7 叶子正交：任意入口 × 任意叶子组合都走同一条 init 尾部，入口只决定仓怎么来，叶子只决定首轮发什么。

- A/B 对照 = 新旧各跑一遍对比，用来证明问题不是新改动引入的
- 归一化 = 比对前先把已知噪声（时间戳、仓路径、项目名）替换成占位符，让比对只剩实质差异
- 探针仓 = 复制出来专门做破坏性试验的仓副本（不动原件）
- metric_key / METRIC_KEYS = 台账「主指标是哪个字段」的配置名 / contract 里声明可用指标的集合（发现⑯即两者对不上）
- worktree = 同一个 git 仓库检出多个工作目录（这里用来同时保留新旧两版模板）
- FIRST-ROUND = 只在首轮（run=1）注入给 agent 的提示段
- check-source-cal = 对照尺来源校准检查（贴文献尺前先本机复算过线，防直接抄表）
- CSV = 逗号分隔的数据表格文件（Comma-Separated Values）；manifest = 数据集「身份证」文件（行数、sha256、来源等元信息）
- symlink = 软链接（指向原文件不复制内容）；sha256 = 文件内容指纹（内容变一个字节指纹就变，用来锁数据版本）
- agent = AI 助手（读仓内流程文档自主干活的 Claude 会话）；plain_recipe = intent 里记的「朴素基线用什么规则」配方
- 泄漏（leak）= 评测时模型间接看到了答案，分数虚高不可信；BestBeamK 格子 = `cellId/beamId/角度/RSRP_dBm` 四段测量记录，16 列已按强度降序排序，标签=最强波束的 beamId（⑱：暴露集未声明时「被测子集」默认=全部 16，规则输出与标签重合）
- ledger_midpoint = 台账中点占位尺（校准不过线时先落的中庸参照值）
- 兜底段 = 满 10 轮还没公开对照尺时，运行上下文自动补发的提醒段（区别于首轮 FIRST-ROUND 主动提示）
- reference_anchor.json = 贴过公开对照尺后落盘的锚值文件；存在即视为「已有尺」，兜底不再提醒
- immutable 护栏 = 手动跑前检查脚本，发现合同/实验代码等不可变文件被改就拒绝（exit 2），还原后放行
- dest = 新建项目仓的目标目录（destination）
- 骨架 = scaffold 装进新仓的模板底子（合同、脚本、说明文件等）
