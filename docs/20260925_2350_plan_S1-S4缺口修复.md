## 0. 结论先行

核验结论：steer 的**口径层**（答卷 → resolved lock）在 S1/S2/S3 全部正确；断的是**落位层**——scaffold 只写 lock 文件，不把 lock 渲染成产物形态（README 配置块、TSV 表头、起步尺子 intent），且 scaffold 与 gate 自相矛盾（自拷贝入口脚本）。headless（`--answers`）模式下这些原靠交互 agent 人工接线的步骤无人接力 → 五判据结构性挂。修复原则：**让 scaffold 把 resolved lock 落位，而不是要求人二次接线**。

## 说人话

体检发现：答卷（考试说明）都能正确存档，但脚手架只把答案锁进抽屉，没把它抄到工位上看的看板（README 配置块、台账表头、起步尺子）上，还把一个不该带的工具箱带进了交付品、自己跟门禁打架；另外「从零新建」的骨架本身有个参数对不上的天生缺陷。计划就是：让脚手架自己完成从「存档」到「上墙」的全部抄写，删掉不该带的工具箱，修好骨架参数，再从头把 S1/S2/S3 三个场景各跑一遍验收。

## 缩略语

- S1–S4 = 从数据新建 / 模板迁移 / 答卷优先改造 / plain 落位（四场景）
- scaffold = 脚手架（new-project.sh 立项流程）
- gate / 门禁 = nn-doctor、verify-migration-complete.sh 等自动检查
- O3 / D2 / E5 = 答卷题组编号（O3=起步尺子口径、D2=数据划分、E5=台账列）
- intent = `saved/baseline_start_intent.json`（起步尺子落盘文件，auto-run 首轮读取）
- TSV = Tab 分隔的台账文件（`_runs/results.tsv`）
- IMMUTABLE / NN_RELAUNCH = 不可变路径标记 / 重立项环境变量（声明核改合法）
